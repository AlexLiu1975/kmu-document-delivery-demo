# KMU 公文登記／查詢公開測試版

前端透過 Firebase 匿名登入、Firestore 交易及即時監聽共用測試資料。請勿輸入真實公文或個人資料。

## 四態流程

- P：未收文，灰色。
- R：已收文，紅色。
- B：已退文，橘色。
- A：已歸檔，綠色。

收文允許新文號、P 或 B 轉成 R；退文只允許 R 轉成 B；歸檔只允許 R 轉成 A。歸檔後不可再收文或退文。

退文交易一次更新狀態、退文次數、最近退文日期／原因／職號、最後更新時間，並新增歷程。再次收文更新收文日期並保留退文資訊；歸檔更新歸檔日期。歷程維持不可修改或刪除。

查詢、最近登記結果及圖形會在資料同步時重新顯示。10×10 每頁顯示末兩碼，年度三碼＋類別三碼（110 創稿／000 收發文）＋流水號四碼組成完整文號；頁碼 00–99。點選已存在文號開啟查詢；P／B 可在資料明細點「收文」。尚未登記的格子保留點選收文。

舊中文狀態透過共用狀態模組讀取，下一次操作會寫入標準代碼；舊 3＋2＋5 與 3＋3＋4 欄位組合皆受規則支援。舊資料缺少新增日期欄位時顯示「—」；未保存退文次數的資料自本次升級後開始累計，原始歷程仍保留。

## 測試

```sh
npm ci
npm test
npm run test:rules
```

Firestore 模擬器需要 Java 21 以上。測試包含四態轉換、1151103143 重複退文／收文／歸檔、舊狀態相容、文號組成、規則與歷程不可修改。

## 上線順序

**先部署 Firestore 規則，再發布前端。** 舊規則只接受中文狀態及原有欄位，會拒絕新版本的狀態碼與日期欄位。

```sh
firebase login
firebase deploy --only firestore:rules --project kmu-document-delivery
```

確認部署成功後再將修正分支合併到 GitHub Pages 使用的分支。本次提交不會修改既有公文資料，也不會自動修正歷史上狀態與退文事件不一致的紀錄；這類資料須先比對完整歷程，避免覆蓋後來的再次收文。
